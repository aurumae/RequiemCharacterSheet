# Android port plan

**Revised 5 November 2026.** The parity baseline is iOS commit `506ea78` on `main`, 12 commits after the initial review at `a51e9af`.

Build the Android app in Kotlin and Jetpack Compose in an `android/` directory beside the Xcode project. Continue developing the iOS app in Swift and SwiftUI. Give both apps the same book catalogs, character-file format and examples of correct rules behavior. This lets a book correction reach both apps in one edit and gives each platform control over how players use the sheet.

## Source control

Keep both apps in the existing `aurumae/RequiemCharacterSheet` repository, with `main` as the integration branch. A fork or separate repository would add a synchronization step each time a catalog, save format or shared test case changes. Keep the Xcode project in its current location. Android Studio opens the new sibling `android/` directory. Put shared save examples and rules test cases in `shared/fixtures/`; both builds read the existing catalogs from their current location.

1. **Day-to-day work.** Start each feature from an up-to-date `main` and merge it through a small pull request. The first shared branch is `shared/save-contract`; the phone editor can follow on `android/blank-sheet`. Merge each when its tests pass so the next piece starts with the latest iOS changes. You can keep Xcode open on your own iOS branch. On one machine, use a second Git worktree for simultaneous Android work; on separate machines, use ordinary clones of the same remote. [Git worktrees](https://git-scm.com/docs/git-worktree)
2. **While Android catches up.** Ship iOS features as they are ready. For a feature that affects both apps, include a sample character or rules example showing the new behavior. If Android support will follow, link an Android parity issue to the original pull request and record which save version each app supports. For example, if iOS introduces schema 10, commit a v10 fixture and verify the v9 Android reader refuses to overwrite it until v10 support lands.
3. **Checks and releases.** Run the affected platform’s tests for platform-only edits and both suites for shared rules, catalogs or saves once both runners exist. Tag builds by platform, for example `ios/v1.2.0` and `android/v0.1.0-alpha.1`. Each app can ship from its own tested commit on its own schedule.

## Architecture and ownership

- **Shared resources.** Keep the three JSON files in the existing iOS catalog directory initially. Point the Android Gradle assets source set at that directory. Both builds should load Requiem core first, then the remaining files by filename, retaining the first entry for a duplicate ID of the same kind. Keep unknown catalog IDs on a sheet and skip unknown effect types when evaluating rules. The nine attributes, skill definitions and Blood Potency table currently live in Swift. Cover their values and ordering with shared tests as they move into Kotlin. [Bundled catalogs](../RequiemCharacterSheet/Catalogs) · [Trait definitions](../RequiemCharacterSheet/Models/TraitDefinitions.swift)
- **Game rules.** Start with a plain Kotlin/JVM `:rules` module and pass it the catalog. Route a committed player edit through one operation that checks any creation limit, applies the change and its consequences, compares trait levels, then updates the log and paid dots together. iOS observes this difference in the sheet view. On Android, Compose redraws, save retries, and restoring a sheet must never replay a purchase. Keep trial edits used to calculate picker availability separate from committed edits. [Swift change recorder](../RequiemCharacterSheet/Views/CharacterSheet/CharacterSheetView.swift) · [Trait keys and log entries](../RequiemCharacterSheet/Models/Experience.swift)
- **Android app.** Use an `:app` module for the file repository, screen ViewModels and Compose UI. A screen observes immutable state via `StateFlow` and sends player actions to its ViewModel. Use Material 3 search, sheets, dialogs and system Back. Carry over the parchment, ink, dot notation and existing Dark Pack attribution. Give the long sheet a section chooser so a player can jump directly from a power to Health. [Android architecture guidance](https://developer.android.com/topic/architecture/recommendations)
- **Cost of this choice.** Each new mechanical rule needs a Swift and a Kotlin implementation. The shared examples below make differences observable. Kotlin Multiplatform is a viable later step for a calculation engine with two native UIs. Adopting it now would also put a Kotlin framework into the Xcode build and require adapting the observable Swift models. Revisit it if maintaining two implementations becomes a recurring source of fixes. [Kotlin Multiplatform for shared business logic](https://developer.android.com/kotlin/multiplatform)

## Character compatibility

Use app-private storage with one JSON file per character UUID. **Write schema 9 and read versions 1–9.** Keep the existing coverage for unversioned saves, legacy damage boxes, named skills, older clan-bane state, catalog/custom sources, nested UUIDs and ordered marks. Preserve fractional seconds in Foundation timestamps, including log dates. The old iOS UserDefaults migration belongs to iOS. [Swift character codec](../RequiemCharacterSheet/Models/Character.swift) · [Swift Foundation date representation](https://github.com/swiftlang/swift-foundation/blob/main/Sources/FoundationEssentials/Date.swift)

| Save introduced | Compatibility check |
| --- | --- |
| v7 | Preserve rituals, Devotions, the chosen Mystery, Coils and Scales, including custom entries. Older saves default to empty collections and no chosen Mystery. |
| v8 | Preserve `xpMode`, `changeLog` and `paidDots`. A purchased dot belongs to a trait key such as `attribute:stamina` or `merit:<row UUID>`. Match Swift’s UUID spelling in keys so a later refund finds that purchase. Older saves retain their earned Experiences, all available to spend. |
| v9 | Preserve optional `creation`, the two category-priority maps, the favoured Attribute, bonus XP and the optional creation flag on log entries. Include both an early v9 guided save with no priority maps and a current mid-creation save. Missing maps mean the choices are still unassigned. An absent creation object means an ordinary sheet. |

Serialize file operations off the UI thread, use atomic replacement and compare decoded, normalized contents before updating the edit timestamp. Preserve unsupported or damaged files and explain their status in the list. Persist accepted edits during use, flush pending changes on Save and Back, and surface write failures. Restore the open character by UUID after Android recreates the process. A background callback alone is insufficient to protect a player's edits. [Android saved state](https://developer.android.com/topic/libraries/architecture/saving-states) · [AtomicFile and concurrency](https://developer.android.com/reference/android/util/AtomicFile)

## Visual alignment before the remaining sheet sections

The 15 iOS App Store screenshots supplied on 4 November 2026 are the visual reference. The `android/visual-parity` branch establishes this appearance for the existing Android library, sheet and change log before the rest of milestone 3 is added.

- Use the original `VtRBorder_NewStyle` paper and centered logo, Caslon Antique for section headings and trait labels, Mrs Eaves Small Caps for categories, and Mrs Eaves Roman as Caslon’s accented-letter fallback. The primary ink color is `#581A12`; section bands are `#F2F2F7`.
- Use flat white rows with subtle separators. Character names, clan/covenant details and relative edit times follow reference 01. Save confirms without leaving the sheet; Back saves and returns to the library.
- Keep editing on the sheet, as requested. Draw red base dots, black bonus dots, and square damage marks. The 5 November refinement uses the iOS spacing: 20 dp marks on a 24 dp pitch. Tap the attribute or skill name for a dropdown of legal base ratings with full-sized menu rows. Attributes start at 1 and skills at 0; both cap at max(5, Blood Potency), never above 10. Ratings stack below labels and Health wraps on small screens; the logo contracts in landscape and above the keyboard.
- Present the XP badge, earned/spent/available values and a separate dated Change Log using references 09–10. Keep the paper theme light even when Android is in dark mode. Android supplies its keyboard, menus, dialog behavior and accessibility actions.
- References 03–06, 08, and 11–14 also define the styles for the remaining Attributes, Skills, powers, Humanity, sorcery and creation screens. Their unfinished editing features remain in the milestones above; this visual pass does not enable guided creation.

A five-second, tap-dismissible Dark Pack notice appears on launch, using the same text and logo as iOS; the text also remains accessible from About this app. The timer survives rotation.

The Android resources are exports of the supplied artwork and fonts; the screenshot files themselves remain outside the repository. The app module contains the theme, shared controls and native sheet layouts. Continue using those components for new sections.

## Milestone 3 delivery slices

Visual alignment is accepted on the Galaxy S24 FE. The first functional slice is on `android/core-sheet`:

1. **Character details, Attributes and Skills.** All nine identity fields, catalog choices for Mask/Dirge and Clan/Covenant, custom text, nine Attributes, 24 Skills, and multiple editable Specialties. The shared rating control supplies compact dots, legal name menus and accessibility adjustments. A section menu navigates the longer sheet. Attribute bonuses use the book effects, excluding bonuses that only apply to dice rolls. All committed rating changes use the paid-dot ledger; Specialty renames do not charge XP. `core-advancement.json` exercises the same sequence in Swift and Kotlin.
2. **Powers and personal traits.** Disciplines and Merits with searchable catalog choices, details, custom entries and prerequisite warnings; Aspirations and the Bane picker with its three-entry limit and clan-bane switch.
3. **Play trackers and Humanity.** Willpower marks, Blood Potency/Vitae, Armor and derived values, Humanity and Touchstones, Beats and earned Experiences. Humanity and Blood Potency losses never refund XP.
4. **Sorcery and advancement completion.** Rituals, Devotions, Mysteries, Coils and Scales, including free ritual slots and the dependent XP prices. Verify complete ordinary play and advancement before calling milestone 3 finished.

The first slice does not enable guided creation or editing the remaining sections. Existing saved data in those sections stays intact. The original Xcode checkout remains on its own branch; integrate the reviewed Android branches into `main` in their existing order.
